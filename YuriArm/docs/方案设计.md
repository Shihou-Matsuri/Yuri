# YuriArm：彩色立方体"病灶切除"抓取方案设计

> 目标：移动平台上搭载 LeRobot SO-101 从动臂，从一堆不同颜色的 30mm 立方体中，
> 只把**指定颜色（病灶）**的立方体移走；**不碰任何非指定颜色（正常组织）**的立方体。
> 碰一次扣分，移走一个加分（不同颜色分值可不同）→ 追求"零扣分 + 全部移走"的最高分。
> 版本：v0.3（无线执行端选型 ESP32-S3）

---

**核心结论先行**
1. **用夹子做"顶置笼式抓取"**：3D 打印超薄细爪（约 2mm 厚）+ 从正上方垂直下压套取，
   配合 **wrist_roll 选最空对面**下指，方块高度上只占用 2 根 2mm 手指。
2. **感知"全局俯视 + 局部校正"**：C922 俯视建图 + ArUco 测臂基座位姿；
   第二相机（无线 ESP32-CAM 或 USB）做抓取前微调与抓取成功验证。
3. **规划原则"高空过、垂直落"**：转移路径 z≥60mm，只在目标正上方垂直下降/上升，
   物理上杜绝扫到邻居；先清"紧贴目标"腾缝隙，四边均 <3mm 的方块跳过保零扣分。
4. **夹持判定用电机负载**：合拢时 Present_Load 跳变=夹住，限速限流防夹碎。
5. **无线架构"笔记本大脑 + ESP32-S3 执行"**：笔记本跑感知/规划，整段轨迹经 WiFi 下发，
   ESP32-S3 本地执行（轨迹缓冲 + 看门狗 + 本地急停），机器人无线自由移动。
6. **移动策略"停车-抓取-停车"**：小车俯视相机闭环泊位（±5mm），收集进车载料篮，
   收完整车开出赛场 = 全部"移走"。

### 1.1 两种部署形态（软件完全兼容）

## 2. 硬件设计

### 2.1 末端：现有夹子 + 3D 打印"细爪"（核心 Trick）

**为什么夹子也能不碰邻居：**
- 平行夹爪的碰撞风险来自"侧向包夹"。改成**从正上方下压、套住方块顶部再合拢**，
  手指在方块高度上的投影只有 2 根手指的厚度；
- 再配合 **腕部旋转（wrist_roll）选择下指方位**：方块有 4 个侧面，
  永远挑**缝隙最大的一对对面**下指 → 被围住时也能从最空方向下手。

**3D 打印手指设计要点（代替原装爪指）：**
| 参数 | 建议 | 理由 |
|---|---|---|
| 手指厚度 | ≤2mm | 缝隙 ≥3mm 即可伸入（30mm 方块 + 两侧各 2mm 手指 ≈ 34mm 开度需求） |
| 手指长度 | 35–45mm（覆盖方块上半部，指尖到离桌面 8–12mm） | 从顶部套住，提升抓持稳定 |
| 开度 | 能开到 ≥36mm | 30mm 方块 + 2×手指 + 余量 |
| 指尖 | 外侧倒圆角/斜角 | 万一擦到邻居，滑开而不是推动 |
| 指内面 | 热熔胶点 3–4 个防滑点（或 1mm 硅胶条，厚度计入 2mm 指标） | 防滑、防夹碎 |
| 刚度 | 背部加一条加强筋（T 形截面） | 2mm 薄壁易弯 |
| 快换 | 螺丝固定，做"长细爪/短粗爪"两套 | 常规用短粗、密集用长细 |

**夹持判定（不用真空）——电机电流/负载：**
- LeRobot 的 `FeetechMotorsBus` 可读电机 **Present_Load / Present_Current**；
- 合拢过程中负载突然跳变（碰到方块）→ 判定夹住 → 保持力矩并提升；
- 同时用第二相机确认方块已离开原位/在爪下（双验证）。
- 合拢限速 + 设定负载上限，超过即停，避免夹碎方块。

### 2.2 小车
- 3 舵机常见布局：2×驱动 + 1×转向（或 2 驱 + 1 抬升/料斗）。由 ESP32-S3 的 UART2 总线驱动。
- **闭环定位**：不依赖轮子里程计（会漂）。俯视相机实时测车顶 ArUco 码位姿，
  "移动一小步→重新测位→纠偏"循环，泊位误差收敛到 ±5mm / ±1°。
- **低速**：近场移动速度 ≤30–50mm/s，车身路径用障碍膨胀（半径=立方体+车宽/2+余量）规划，
  保证车体不压到任何方块。
- **稳定性**：电池放底盘最低处、重心压低；机械臂底座与车架刚性连接 + 橡胶垫减震；
  移动/抓取分开进行，避免底盘晃动影响精度。

### 2.3 料篮（投放）
- 车尾/车侧挂一个浅料篮（亚克力/纸板 + 热熔胶），臂在"高空"把方块放进篮内，
  全程不经过桌面其他方块上方——转移路径短、丢落风险低。收完最后一颗 → 小车开出赛场。
- 若规则要求投到指定区域：小车开到该区域边缘，臂把篮内方块依次放入/倒出。

### 2.4 无线执行端：ESP32-S3（本版新增核心）

**选型**：ESP32-S3-DevKitC-1（N8R8：8MB Flash + 8MB PSRAM，约 ¥25–40）。
选 S3 而非原版 ESP32：USB-C 原生烧录/串口调试、双核更快、PSRAM 余量大、3×UART。

**总线接口**（关键，绕开原 USB 驱动板通信）：
- 飞特 STS3215 是 **1Mbps 半双工单线 TTL 总线**，ESP32 的 UART 不能直连，
  使用 LeRobot/Waveshare 文档配套的 **Bus Servo Adapter (A)**，接它板上的 **UART 3 针口**
  （TX/RX/GND），两个黄色跳线帽放在 **A（UART-SERVO）**；该板自带方向控制，**不需要 MAX485/DE**；
- **UART1 → 从动臂总线，UART2 → 小车总线**；UART0 留给调试（日志走 USB-CDC，不占 UART0 也可）。
- 方向切换由 Waveshare 适配器完成；固件仍按 Feetech 协议 `FF FF ID LEN INST ... CHK` 收发。

**通信协议（笔记本 ↔ ESP32-S3，WiFi TCP）**：
- ESP32-S3 开 **WiFi AP**，笔记本直连（免场地路由器）；TCP 可靠传输，报文紧凑二进制或 JSON；
- 下行指令：`TRAJ`（轨迹点列表：时间戳+关节/舵机目标）→ `GO`（开始执行）→ `STOP/ESTOP` → `READ`（读遥测）；
- 上行回报：`DONE / ERROR / HEARTBEAT` + 遥测（关节位置/负载）。
- **关键设计：下发"整段轨迹"由 ESP32 本地执行** → WiFi 抖动/断连不影响中途动作。

**本地安全（无线方案底线）**：
- **看门狗**：200ms 内未收到任何指令/心跳 → 立即停止/回安全位，防止断线乱跑；
- **本地急停**：ESP32 直接读舵机负载，碰撞瞬间本地停止回退（不等笔记本往返，比有线更快）；
- 上电默认 torque off / 安全位，只有收到明确 GO 才运动。

**固件**：Arduino（ESP32 Arduino 核心）或 PlatformIO；目录见 §5 `firmware/`。

### 2.5 供电（3S LiPo 单包）
```
3S LiPo(11.1V) ─┬─ 降压 7.4V(≥5A) ──► 从动臂总线（STS3215，峰值电流靠电容组缓冲）
                ├─ 12V：3S 直供（若小车舵机规格允许 11.1–12.6V）或升降压到 12V ──► 小车总线
                └─ 降压 5V(≥2A) ──► ESP32-S3 / 适配器 / ESP32-CAM
```
- 所有 GND **共地**，否则总线通信会乱；
- 原两块 Waveshare "驱动板"不再作为 USB 通信主通道，可留作**供电模块**
  （USB 不接，从总线端子取 VCC）或调试备用；也可直接用其 USB 口接电脑做舵机 ID/参数配置。
- 多备一块电池轮换；正式赛前测满电/低电量两种状态下的舵机一致性。

## 3. 感知设计（复用 YuriEye + 增补）

### 3.1 双相机分工
| 相机 | 安装 | 作用 |
|---|---|---|
| C922（YuriEye 已标定） | 3D 打印支架俯视，固定于赛场上空 | ①全局地图：所有方块位置+颜色（单应变换→桌面 mm 系）②ArUco 测小车/臂基座位姿 ③每次操作后重扫验证 |
| 第二相机 | 小车斜下看抓取区 | ①抓取前把夹子对准方块中心（视觉伺服微调）②验证夹起/投放 ③俯视被臂遮挡时的局部兜底 |

第二相机两种接法（二选一）：
- **无线：ESP32-CAM**（OV2640，WiFi 传 JPEG，640×480 约 10–20fps）——车无线化，推荐；
- 有线：普通 USB 相机走长线到笔记本——距离 ≤1–2m 时可接受，需带供电 USB HUB。

### 3.2 标定流程（棋盘格已有，一次性）
1. **内参**：YuriEye `tools/calib_camera.py` 用棋盘格标定（≥8 张不同角度）→ 去畸变。
2. **俯视→桌面单应**：把棋盘格/ArUco 网格平铺桌面 → 求图像像素→桌面 mm 的透视变换；
   桌面是平面，一张单应即可，精度可到 ±2–3mm。
3. **方块坐标**：YOLO 框中心 → 单应 → 桌面 (x,y)，顶面 z=30mm（抓取点）。
4. **臂基座位姿**：车顶/臂底座贴 ArUco，俯视相机解出世界→臂基座变换；
   配合 SO-101 正向运动学把桌面坐标转到臂基座系 → IK 求"垂直下压"位形。
5. **第二相机偏移**：量出相机相对夹子的固定偏移（手眼-1 步），
   抓取前用它对夹子位置做闭环微调（≤±3mm 收敛）。
6. **光照/曝光/白平衡**：沿用 YuriEye 做法——固定机位、固定灯光、锁手动曝光/白平衡；
   比赛光照变化时重跑 `calib_color.py`（HSV 兜底）即可。

### 3.3 颜色判定（防误判=防扣分）
- 主检测 YOLOv8m（mAP50 0.949）；对每个检测框**再用 HSV 二次确认**颜色，
  双通道一致才采信，不一致标记"未知"不抓（宁可少抓，不可抓错）。
- 比赛开始后只有 2–4 种目标色：运行时把目标色集合写进配置，
  规划只对"目标色 ∩ 检出集"下发抓取任务。
- 红色/橙色混淆是已知最弱项：加 HSV 复核 + 采信阈值 + 可选"同色一致性"。

## 4. 规划与得分策略（"一分不丢 + 全部移走"）

### 4.1 打分模型
```
总分 = Σ(移走的指定色得分) − Σ(碰到的非指定色扣分)
目标：满移除 + 零接触
```

### 4.2 抓取顺序（贪心 + 风险权衡）
对每个目标方块计算：
- **value**：该颜色分值（赛前从裁判处获取，写进配置）
- **risk**：到最近非目标方块的间距，以及"最空的一对对面"缝隙是否 ≥ 手指所需（2×2mm+余量）
- **access**：该位置是否在臂可达域内、wrist_roll 能否转到最空方位

排序：**按 value 降序**（高分先保），同分按 risk 升序（先做安全/好做的）；
**先移除"紧贴其他目标"的目标**——移走它会给旁边的方块腾出缝隙，让后续更好下手
（缝隙是硬约束，越早腾越有利）。
若时间不足，最后放弃"风险最高 + 分值最低"的目标（宁可少一分，不可碰一次扣更多）。

### 4.3 防碰核心规则（物理层面兜底）
1. **安全地图**：每个非目标方块中心画"禁入区"（方块外扩 3–5mm），
   手指轨迹不得进入他人禁入区（手指 2mm，理论上 3mm 缝就能下指）。
2. **选边下指**：下压前用 **wrist_roll 把手指转到缝隙最大的两个对面**；
   若四个面都 <3mm 缝 → 标记跳过（保零扣分优先）。
3. **高空转移**：所有臂间转移 z≥70mm（方块高 30mm + 裕量），不可能碰方块。
4. **垂直下落**：只在目标方块正上方垂直下降；下降前 IK 检查该"井道"不与禁入区相交，
   若相交则换从最空一侧带 5–10° 倾角下压。
5. **低速 + 电流监控**：下降/合拢速度放慢；关节负载突增判定碰撞 → 立即停 + 回退，
   把"碰到"变成"轻碰即退"，最大限度减损。
6. **先夹后提**：负载阈值确认夹住才提升；提升纯垂直，不横向拖。

### 4.4 执行状态机（每颗方块）
```
SCAN(俯视重定位)
→ MOVE_BASE(闭环泊位，ArUco 收敛 ±5mm)     [形态A]
→ PLAN(选边：wrist_roll 挑最空对面；IK 求垂直下压位形)
→ 下发整段轨迹(TRAJ+GO) 给 ESP32-S3
→ ESP32 本地执行：TRANSIT_HIGH(z≥70mm)→DESCEND→CLOSE(负载判夹)→LIFT→TRANSIT→DROP
→ VERIFY(俯视重扫：目标消失√ 非目标位置未变√)
→ 更新地图，下一颗
```
> 轨迹下发后中途动作由 ESP32-S3 本地完成（抗 WiFi 抖动）；笔记本只负责建图、规划、
> 发轨迹、收遥测、验证结果。抓取段相机验证：第二相机（若 USB/无线可用）实时看爪下。

### 4.5 异常与容错
| 异常 | 处理 |
|---|---|
| 夹不住/滑脱 | 重试 ≤2 次（重新定位+换边+微调）；仍失败→标记跳过，不硬来 |
| 负载超限（疑似夹到邻居/夹碎） | ESP32 本地急停 + 张开回退，笔记本重扫地图后继续 |
| WiFi 断连 | ESP32 看门狗停止/回安全位；笔记本重连后重发当前轨迹 |
| 中途掉块 | 俯视检测到"目标仍在/出现在新位置"→ 更新地图后重排，再抓 |
| 疑似碰了非目标 | 俯视比对位置变化→记录扣分；后续规划把它当"新障碍"避开 |
| 相机被臂遮挡 | 俯视用于建图/验证，抓取段用第二相机兜底 |
| 小车泊位偏差大 | 闭环重泊 1 次，仍超差→换可达位形/换泊位点 |

## 6. 里程碑（建议：先有线跑通，再无线化）

## 7. 风险与缓解（汇总）

| 风险 | 缓解 |
|---|---|
| 夹爪碰邻居 | 细薄手指 + 垂直"套取" + wrist_roll 选最空对面 + 高空转移（4.3） |
| 缝隙太小下不去 | 先移除紧贴目标腾缝；四边均 <3mm 则跳过保零扣分 |
| 手指薄易弯 | T 形加强筋、PETG 打印、做两套（长细/短粗） |
| 夹碎/夹滑 | 合拢限速 + 负载上限即停；指内热熔胶/硅胶防滑点 |
| WiFi 断连/抖动 | 整段轨迹本地执行 + 200ms 看门狗停止/回安全位；TCP 重连续传 |
| 适配器方向切换/UART 电平 | 使用 Waveshare UART 模式（跳线 A），先按官方 TX-TX/RX-RX，不通再试交叉 |
| 总线供电不足（峰值电流） | 独立降压 + 舵机总线电容组；满/低电量双测 |
| 手臂晃动/底盘不稳 | 慢速、重心压低、抓取时停车、橡胶垫减震 |
| 颜色误判（红/橙等） | YOLO+HSV 双通道复核；未知色不抓 |
| 俯视被臂遮挡 | 第二相机局部兜底；俯视只负责建图/验证 |
| 时间不够 | 按 value 优先、risk 舍弃；满移除失败也要保零扣分 |

---

## 8. 一句话总结

**用夹子做"顶置笼式抓取"（超薄细爪 + 垂直套取 + wrist_roll 选边），
笔记本做大脑（俯视建图/规划），ESP32-S3 做无线执行端（整段轨迹本地跑 + 看门狗 + 本地急停），
"高空过、垂直落"把不碰邻居变成物理约束；顺序上高分先保、紧贴目标先清、危险后置，
实现"全部移走 + 零接触"的最高分目标。**
